# Установка wslbin

Коротко об установке - в [README](README.ru.md#установка). Здесь остальное: все параметры, куда ставится
wslbin, что доказывают проверки, обновление, удаление и установка без сети. [English](INSTALL.md).

Релиза ещё нет, а сайт (GitHub Pages) не опубликован, поэтому команды ниже заработают после первого релиза и
первого деплоя Pages. Чтобы пользоваться wslbin раньше, см.
[CONTRIBUTING.md](CONTRIBUTING.md#build-and-use-from-source) (на английском).

## Требования

- Windows 10 22H2 или Windows 11, x64.
- WSL 2 с дистрибутивом.
- Windows PowerShell 5.1 или PowerShell 7 (установщик работает в обоих).

## Установка

```powershell
irm https://quatrebi.github.io/wslbin/install.ps1 | iex
```

Это загрузчик. Он читает с сайта список релизов, скачивает последний архив с GitHub Releases, проверяет его и
запускает установщик из архива. В консоли он спросит то, что не задано: для кого ставить и подключать ли
автодополнение. С `-Quiet` он ничего не спрашивает.

Параметры принимает блок скрипта:

```powershell
& ([scriptblock]::Create((irm https://quatrebi.github.io/wslbin/install.ps1))) -Scope AllUsers -Link make,rsync,dig -Completion pwsh,clink -Quiet
```

Конкретная версия: добавьте `-Version` с номером со [страницы релизов](https://github.com/quatrebi/wslbin/releases),
например `-Version 1.2.3`. Для первой строки то же делают переменные окружения `WSLBIN_VERSION` и `WSLBIN_SCOPE`.

Загрузчик:

- запускает установщик в отдельном PowerShell, поэтому политика выполнения вашего не мешает;
- ничего не оставляет от скрипта в вашей сессии; код выхода - в `$LASTEXITCODE`;
- короткий, так что его можно прочитать до запуска: [`site/install.ps1`](site/install.ps1).

## Параметры

| Параметр | Что делает | Загрузчик | `setup\install.ps1` | `setup\uninstall.ps1` |
| --- | --- | --- | --- | --- |
| `-Version` | какую версию ставить; без него - последнюю | да | - | - |
| `-Scope` | `CurrentUser` (по умолчанию) или `AllUsers`; см. [область установки](#область-установки-и-права-администратора) | да | да | - |
| `-InstallDir` | другая папка (для удаления: какую установку удалять) | да | да | да |
| `-Link` | для каких утилит сделать обёртки, например `make,rsync,dig` | да | да | - |
| `-Completion` | `pwsh`, `clink` или `pwsh,clink`: подключить автодополнение в оболочку | да | да | - |
| `-NoPath` | не трогать PATH | да | да | да |
| `-Force` | поставить ту же версию ещё раз или более старую, чем установлена | да | да | - |
| `-Quiet` | ничего не спрашивать | да | - | да |
| `-VerifyAttestation` | ещё и доказать, откуда архив (см. [ниже](#что-доказывают-проверки)) | да | - | - |
| `-Purge` | удалить и `wslbin.ini` | - | - | да |

Загрузчик передаёт установщику из архива `-Scope`, `-InstallDir`, `-Link`, `-Completion`, `-NoPath` и
`-Force`; `-Version`, `-Quiet` и `-VerifyAttestation` он использует сам. Остальные параметры этих скриптов
служебные или нужны тестам (форк может заменить репозиторий загрузчика).

Коды выхода `setup\install.ps1` и `setup\uninstall.ps1`:

| Код | Значение |
| --- | --- |
| 0 | готово |
| 1 | установка: готово, но что-то, что её не остановило, не удалось (профиль не в UTF-8 оставлен как есть, обёртку не удалось создать); удаление: что-то не удалось убрать (программа, которая работает, держит свой файл) |
| 2 | сбой |

## Область установки и права администратора

| | Для вас (`CurrentUser`) | Для всех (`AllUsers`) |
| --- | --- | --- |
| Папка | `%LOCALAPPDATA%\Programs\wslbin` | `C:\Program Files\wslbin` |
| PATH | пользователя | машины |
| Права администратора (UAC) | нет | да |

- Без `-Scope` ставится для вас, если только wslbin уже не установлен для всех пользователей: тогда
  обновляется та установка.
- Для всех пользователей с `-InstallDir` папка должна быть такой, которую могут менять только администраторы.
  Новая такой и создаётся; существующая, которую могут менять другие, не принимается.
- Папка, в которой есть файлы с именами файлов wslbin (`LICENSE`, `manifest.json`, `setup\`) и которая не
  установка wslbin, не принимается ни для какой области: эти файлы принадлежат чему-то другому.
- Если wslbin установлен и в другой области, установщик скажет об этом до того, как создаст новую установку.
  Из двух запускается та, что для всех пользователей: она раньше в PATH.
- В одной области одна установка: вторая в другой папке не ставится, даже с `-Force`.

Что делает копия с правами администратора (`-Scope AllUsers`):

- Она ставит только саму программу и ничего больше, в папку, куда пишут только администраторы.
- Она ещё раз сверяет SHA256 каждого файла перед записью; что она сделала, видно в её окне.
- Она ничего не запускает из папки установки.
- Это защищает от изменений после проверки. Тому, откуда вы запускаете установщик, доверяете вы сами, как с
  любым установщиком.

`-Link` и `-Completion` выполняются потом от вашего имени, в вашем WSL и ваших профилях. Если установка для
всех пользователей, `-Link` ещё раз попросит права, чтобы записать обёртки. `-Completion` подключает
автодополнение в PowerShell (обе редакции) и Clink и предупреждает, если политика выполнения PowerShell не
даст запустить профиль (тогда: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`).

## Что доказывают проверки

| Проверка | Кто делает | Что доказывает | Чего не доказывает |
| --- | --- | --- | --- |
| SHA256 архива по `releases.json` | загрузчик, всегда | загрузка не повреждена и не подменена по дороге: это хеш, который релиз опубликовал вместе с архивом, и сайт сверил его с хешем файла по данным GitHub | кто собрал архив: хеш и архив происходят из одного проекта |
| `gh attestation verify` | загрузчик, с `-VerifyAttestation` (нужна программа [gh](https://cli.github.com)) | архив собран рабочим процессом релиза этого репозитория из `main` | что код хороший; только эта проверка говорит, откуда архив |
| SHA256 каждого файла по `manifest.json` | установщик | файлы в архиве целые и (для всех пользователей) не менялись после проверки | откуда архив: `manifest.json` лежит в том же архиве |

`wslbin.exe` не подписан Authenticode. Архив должен быть ровно `wslbin-<версия>-win-x64.zip` из релиза
`v<версия>` этого репозитория.

## Обновление

Обновление - та же команда.

- Более новая версия ставится.
- Для такой же версии установщик пишет, что она уже установлена (`is installed already`; `-Force` поставит
  её снова; папку без `wslbin.exe` он ставит заново и так).
- Более старая версия не ставится (`-Force` вернёт её).
- Файлы заменяются все вместе или ни один. Работающие `wslbin.exe` и обёртки сначала переименовываются в
  `.old` и удаляются сразу или при следующем запуске.
- Файлы, которых в новой версии больше нет, удаляются. Ваш `wslbin.ini` не трогается.

## Удаление

«Параметры» > «Приложения» > wslbin > «Удалить» или `setup\uninstall.ps1` в папке установки (`-Quiet` ничего
не спрашивает, `-Purge` удаляет и `wslbin.ini`). Запущенный из распакованного архива, он ищет установку в
обычных местах, а файлы архива не трогает.

Он убирает:

- обёртки и файлы wslbin;
- запись в PATH, только если её добавил установщик;
- запись в «Приложениях»;
- подключения в профилях PowerShell и в Clink (те, что относятся к оставшейся установке, сохраняются);
- блок для ИИ-агентов.

Если обёртка или `wslbin.exe` используется, установка и её запись в «Приложениях» остаются, и удаление можно
запустить снова, закрыв программу. Больше установщик в реестр ничего не пишет.

## Установка без сети

В архиве (`wslbin-<версия>-win-x64.zip` на [странице релизов](https://github.com/quatrebi/wslbin/releases),
рядом `.sha256` и `SHA256SUMS.txt`) лежат:

- `wslbin.exe` и `LICENSE`;
- `manifest.json`: каждый файл с его SHA256;
- `setup\install.ps1`, `setup\uninstall.ps1` и `setup\common.ps1`.

Распакуйте архив и запустите установщик из распакованной папки:

```powershell
.\setup\install.ps1 -Link make,rsync,dig -Completion pwsh,clink
```
