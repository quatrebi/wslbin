Переменные

Переменные Windows в вашей команде (PowerShell $env:NAME и $(...), cmd %NAME%) подставляет ваша
оболочка до запуска wslbin, в любом режиме. Потом wslbin переводит пути в полученных значениях:
    make VERSION=$env:APP_VERSION
    rsync -av "$(Get-Location)\dist\" host:/srv/       (PowerShell)
    make VERSION=%APP_VERSION%                          (cmd)

Переменные и команды Linux (--wslbin-sh): $HOME, ${VAR}, $(команда), `команда` подставляет bash.
В PowerShell пишите их в одинарных кавычках, иначе PowerShell возьмёт их первым.
    make --wslbin-sh 'OUT=$HOME/out' 'TAG=$(git rev-parse --short HEAD)'
Для цепочек подлиннее: wslbin -c "...".

Переменные Windows, которые видят программы Linux
  pass_env = KENV_*, APP_*, CI        в wslbin.ini; * и ? - шаблоны, регистр не важен.
  - Каждая подходящая переменная вносится в WSLENV на время вызова, и программа её видит.
  - Значение, которое является путём Windows или списком путей через ;, переводится
    (C:\x\y -> /mnt/c/x/y; C:\a;D:\b -> /mnt/c/a:/mnt/d/b). Любое другое значение приходит как есть.
  - PATH и WSLENV не передаются никогда (Windows-овый PATH заменил бы PATH Linux).
  - Имена, которые вы сами внесли в WSLENV, продолжают работать, с вашими флагами.
  - wslbin никогда не меняет окружение самого wsl.exe: он читает из него SystemRoot, TEMP и т. п.
  - Посмотреть план: <утилита> --wslbin-explain печатает в stderr строку "wslbin: env ИМЯ" для
    каждой переменной (со значением только там, где путь был переведён: в значениях могут быть
    секреты).

Папки для программ в WSL
  path = ~/.local/bin, ~/.cargo/bin     в wslbin.ini
  bash запускается без вашего профиля (так запуск быстрый), поэтому программы, установленные через
  pipx, cargo или go, сами не находятся. Эта настройка ставит папки в начало PATH.
