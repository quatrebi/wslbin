Linux tools from WSL, as plain Windows programs. Linux-утилиты из WSL как обычные программы Windows.

Type rsync, make or dig in PowerShell, cmd or an IDE terminal, or start them from any program. Windows paths, wildcards, pipes, colours, Ctrl+C and exit codes work as you expect. Запускайте rsync, make и dig в PowerShell, cmd или терминале IDE, либо из любой программы. Пути Windows, шаблоны, пайпы, цвета, Ctrl+C и коды возврата работают как надо.

PowerShell → WSL
You type in WindowsВы вводите в Windows
Bash gets in WSLBash получает в WSL
PS> rsync -av *.log C:\backup\
rsync -av *.log /mnt/c/backup/
PS> rsync -av C:\proj\dist\ host:/srv/app/
rsync -av /mnt/c/proj/dist/ host:/srv/app/
PS> make build; $LASTEXITCODE
exit code of make, unchanged
* is left for bash to expand by Linux rules. Everything else you type, such as $ ; | &, quotes and spaces, reaches the utility literally. * остаётся для bash, он раскроет её по правилам Linux. Всё остальное, например $ ; | &, кавычки и пробелы, доходит до утилиты как есть.

One small .exe per utilityОдин маленький .exe на каждую утилиту

Each wrapped utility is a copy of wslbin.exe named after it. Input and output are not intercepted, so pipes and full-screen programs work. Каждая утилита это копия wslbin.exe с её именем. Ввод и вывод не перехватываются, поэтому пайпы и полноэкранные программы работают.

Safe by defaultБезопасно по умолчанию
Only *, ?, [...] and a leading ~ reach bash unescaped. An argument can never run a second command.В bash без экранирования попадают только *, ?, [...] и начальная ~. Аргумент не может запустить вторую команду.
Three modesТри режима
Smart by default, --wslbin-raw for exact arguments, --wslbin-sh for Linux variables and $(...).По умолчанию умный, --wslbin-raw для точных аргументов, --wslbin-sh для переменных Linux и $(...).
See before you runПосмотрите до запуска
--wslbin-explain prints the exact bash command and runs nothing.--wslbin-explain печатает точную команду bash и ничего не запускает.
Tab completionАвтодополнение по Tab
Variants come from bash-completion in WSL, in PowerShell and in cmd with Clink. C:\Prog completes to C:\Program Files\.Варианты берутся из bash-completion в WSL, в PowerShell и в cmd через Clink. C:\Prog дополняется до C:\Program Files\.
Check and manageПроверка и управление
wslbin --doctor checks the setup. --link adds wrappers and offers to install missing utilities with apt.wslbin --doctor проверяет настройку. --link добавляет обёртки и предлагает поставить недостающие утилиты через apt.
Made for AI agents tooИ для ИИ-агентов
wslbin --install-ai-context tells Claude Code and Codex how to call Linux tools on your machine.wslbin --install-ai-context объясняет Claude Code и Codex, как вызывать Linux-утилиты на вашей машине.

InstallУстановка

The installer builds the program from the release source, so it needs the .NET SDK 10 and the Visual Studio C++ build tools. Установщик собирает программу из исходников релиза, поэтому нужны .NET SDK 10 и C++ build tools из Visual Studio.

  1. Download the release filesСкачайте файлы релиза

    You need install.ps1 and SHA256SUMS.txt from the latest release.Нужны install.ps1 и SHA256SUMS.txt из последнего релиза.

    Latest releaseПоследний релиз Source zip (main)Исходники zip (main)

  2. Run the installerЗапустите установщик

    Use the tag of the release and the hash of its source archive from SHA256SUMS.txt.Подставьте тег релиза и хеш его архива исходников из SHA256SUMS.txt.

    powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 `
  -Version v<version> -Sha256 <hash> `
  -Link make,rsync,dig -Completion pwsh,clink

  3. Check itПроверьте

    PS> wslbin --doctor

    More in the README: scopes, configuration, build from source.Подробнее в README: области установки, настройка, сборка из исходников.
